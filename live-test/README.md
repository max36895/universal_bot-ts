# umbot live-test

Консольная проверка работы umbot с **настоящими** платформами. Запускается на
вашем сервере, токены берутся из локального `.env` и никуда не уходят.

В npm-пакет папка не попадает (публикуются только `dist` и `cli`).

## Быстрый старт

```bash
npm run build                          # собрать dist (если запускаете из репозитория)
cp live-test/.env.example live-test/.env
# заполните токены нужной платформы и ID вашего тестового чата
node live-test                         # интерактивное меню
```

Без меню (удобно по SSH):

```bash
node live-test --platform telegram --mode scenarios
node live-test --platform vk --mode webhook
node live-test --platform max --mode register
```

Платформы: `telegram`, `vk`, `max`, `viber`, `alisa`, `marusia`, `smartapp`.

## Режимы

### 1. Прогон сценариев (`scenarios`)

Для каждой реплики из списка («помощь», «текст», «кнопки», «карточка», «галерея»,
«голос», «звук», «шаг» → «Иван», «абракадабра») собирается входящий запрос в
формате платформы **от имени вашего тестового пользователя** и отдаётся в
`bot.run()`. Дальше всё как в проде: адаптер → команды → контроллер → адаптер, и
адаптер отправляет **реальные запросы к API платформы в ваш чат**.

Вывод для каждой реплики:

- `→ POST https://api.telegram.org/bot***/sendPhoto 200 ✓` — каждый исходящий запрос
  (токены в адресе скрыты), статус и текст ошибки API, если она есть;
- `ошибка фреймворка:` / `warn:` — что залогировал umbot;
- для голосовых платформ — JSON-ответ и проверка обязательных полей протокола
  (`протокол ✓` / `протокол ✗ …`).

В конце — итог `✓/✗` по каждому сценарию; код выхода 0, если всё прошло.

Для чат-платформ дополнительно смотрите в приложении: пришли ли сообщения,
кнопки, картинки, голосовое.

Специальные события: у MAX — `bot_started`, у Viber — `conversation_started`
(приветствие возвращается телом ответа, в журнале запросов его не будет — смотрите
вывод `bot.run`). У Алисы и Маруси — health-check `ping`.

### 2. Webhook-бот (`webhook`)

Запускает демо-бота как HTTP-сервер (`LIVE_HOST:LIVE_PORT`). Направьте webhook
платформы на ваш публичный HTTPS-адрес (обычно через nginx/Caddy на этот порт) и
общайтесь с ботом через приложение. Здесь проверяются настоящие события:
нажатие кнопки с payload («Нажми меня» → `addAction`), отправка фото
(`addEvent('photo')`), запуск бота.

В консоли печатается каждое входящее событие, ответ бота и исходящие запросы.

### 3. Регистрация webhook (`register`)

Telegram (`setWebhook`, с `TELEGRAM_WEBHOOK_SECRET`), Viber (`set_webhook`),
MAX (`/subscriptions`, с `MAX_WEBHOOK_SECRET`) — на адрес `LIVE_PUBLIC_URL`.
Для VK, Алисы, SmartApp печатается, где это настроить в консоли платформы.

## Что нужно для каждой платформы

| Платформа | Переменные                                                                 | Подготовка                                                  |
| --------- | -------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Telegram  | `TELEGRAM_TOKEN`, `LIVE_TELEGRAM_CHAT_ID`                                  | напишите боту, узнайте свой chat id                         |
| VK        | `VK_TOKEN`, `LIVE_VK_USER_ID` (+ `VK_CONFIRMATION_TOKEN`, `VK_SECRET_KEY`) | напишите сообществу (иначе VK не даст ему ответить)         |
| MAX       | `MAX_TOKEN`, `LIVE_MAX_USER_ID` (+ `MAX_WEBHOOK_SECRET`)                   | нажмите «Начать» у бота                                     |
| Viber     | `VIBER_TOKEN`, `LIVE_VIBER_USER_ID`, `VIBER_SENDER`                        | подпишитесь на бота                                         |
| Алиса     | `ALISA_TOKEN`, `ALISA_SKILL_ID` — для загрузки картинок                    | без них работает всё, кроме карточек                        |
| Маруся    | `MARUSIA_TOKEN` — для загрузки картинок                                    | ⚠ VK прекратил поддержку пользовательских скиллов с 12.2024 |
| SmartApp  | — (картинки только по `LIVE_IMAGE_URL`)                                    | см. примечание про хранилище ниже                           |

Голос в Telegram/VK/MAX (сценарий «голос») требует `SPEECH_KIT_TOKEN` —
API-ключ сервисного аккаунта Yandex Cloud с ролью `ai.speechkit-tts.user`.

Картинки: по умолчанию генерируются PNG 520×320 (пропорции 13:8 подходят и для
карусели VK). Свои файлы — `LIVE_IMAGE_1..3`.

## Примечания

- **SmartApp**: при `isLocalStorage: true` umbot хранит данные пользователя во
  внешнем хранилище SmartApp Code. Оно ограничивает частоту запросов (быстрый прогон
  сценариев может получить `429 Too Many Requests`) — это видно в журнале.
- **Шаги** на чат-платформах сохраняются в FileAdapter (`live-test/.tmp/db`), как в
  проектах, сгенерированных CLI.
- Артефакты прогона — в `live-test/.tmp/` (в git не попадают).
